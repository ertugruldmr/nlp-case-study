1. Ne yapılır, hangi sırayla (tek LLM çağrısı yok)

S0 YAML konfig (sayfa aralığı, dipnot no) → S1 render + tesseract TSV → S1b RapidOCR ikinci motor → S2 sayfa doğrulama → S3 x-kümeleme tablo yapısı (S3b oran satırlarında motor rol değişimi) → S4 Türkçe sayı grameri (parantez negatif, nokta binlik; tire / boş / sıfır üç ayrı durum) → S5 dipnot bulma (İçindekiler + ofset + başlık doğrulama + "devamı" yürüyüşü) → S6 aday üretimi (4 kanal: char TF-IDF + token-set fuzzy + e5-small + değer çapası, ağırlıklı RRF k=10) → S7 ilişkilendirme (A çapraz kodlayıcı, B değer+rol kuralları, C sözcüksel taban, D LLM seçici kapalı) → S8 çalışma anında kalibre güven → S9 üç grup doğrulama → S10 JSON / JSONL / HTML rapor.

2. Nerede ayrışıyorlar (gereksinim 10)

3. Güven: ham benzerlik değil, dokümanın kendi aritmetiği

  • Dört seviye: hücre (OCR × ayrıştırma × motor uyuşması), satır, tablo (sıralı bileşimler) ve ilişki (kalibre olasılık).
  • Kontrol seti dokümandan: pozitif = bir yaklaşımın kabul ettiği VE değer mutabakatı geçen karar; negatif = herkesin reddettiği. 11 pozitif / 22 negatif (nakit akış sayfaları 9-10 konfigle eklenir). Kabul edilip mutabakat geçmeyen kararlar hiçbir havuza girmez.
  • Yumuşatılmış Platt (a = 10,53, b = -3,70, çıktıda); ayrışan kontrollerde izotonik basamağa çöker, yumuşatmasız lojistik doyar. Jackknife: hiçbir güven 0,037'den fazla oynamaz.
  • Leave-one-out Brier 0,0085 (taban oranı 0,2222; ham füzyon 0,0579), make calibration. Kendi kontrolleri: "bu dokümanda tutarlı", "genelde kalibre" değil.
  • Venn-ABERS aralığı [p0, p1] her ilişkide; en zayıf bağ [0,50, 1,00], konsensüs [0,90, 1,00]. Dürüstlük kaydı: aralık ilişkinin kendi kontrol etiketiyle hesaplanır; etiket çıkarılınca en zayıf [0,00, 1,00]. Aralık bir sıralama aracıdır, kapsama garantisi değil.
  • Eşik: incele ⇔ p < 1 − cinceleme/ckaçırma; 1/20 → 0,95 (7 ilişkinin 6'sı kuyruğa), 1/5 → 0,80 (kuyruk boş). Eşik kaçırma maliyetiyle yükselir; yedek kalibrasyon modu her ilişkiyi kuyruğa gönderir.

4. Doğrulama ve iki gerçek hata

  • Yapısal (dönem sırası, referans aralığı, bulunan başlık, kapsama), biçimsel (gidiş-dönüş ayrıştırma, üç durum, işaret, motor uyuşması, yüzde sınırı), finansal (roll-forward, kategori ve ebeveyn toplamları, genel toplam hipotez oyu, gelir tablosu kaskadı, mutabakat). Değerlendirilemeyen kontrol not_evaluable der.
  • Stoklar 2012: 77.543.097 → 77.943.097 (5 → 9): ikinci motor uyuşmazlığı güveni 0,4'e çeker VE ebeveyn toplamı +400.000 sapar. Finansal Yatırımlar 2012: 4.224 → 4,224: rakamlar aynı, motor kontrolü doğası gereği geçer; ,224 kalıntısını ebeveyn toplamı yakalar. İkisi de düzeltilmez, işaretlenir: sıfır sessiz hata.
  • Mutasyon testli (eval/mutations.py, pakette): alt kalem rakamı, genel toplam, bağlantı satırı bozulmaları 3/3 adlı yakalayıcıyla yakalanır.

  • Puanlayıcı kuralları README 9'da; referans dışı çıkarılmış satır sayısı yazdırılır (0).
